# LKH3 task-assignment tours

These files are task-assignment tours generated by a native ARM64 build of the
LKH3 source bundled with `reference_code/TA-Prioritized/LKH3` (with
`TA-Hybrid/LKH3` available as a fallback).

LKH settings:

- seed: 1;
- runs: 1;
- maximum trials: 1;
- improvement time limit: 1 second;
- candidate count: 3;
- objective: TSPTW makespan.

Each run is seeded with a complete round-robin task assignment, grouped after
the corresponding agent depot. This prevents short runs on large instances
from returning LKH's uninitialized/sentinel makespan while still allowing LKH
to improve the assignment and ordering.

The time limit applies to LKH's improvement phase; matrix loading and candidate
construction can take longer, especially for LARGE instances. LKH is a
heuristic, so these tours are valid generated solutions but are not claimed to
be optimal.

## Included tours

- one offline (`fall`) tour for every one of the 20 map/agent variants;
- one offline (`fall`) tour for every one of the five structured-SMALL
  MG-MAPD agent variants.

There are 25 tours in total. Online frequency workloads, including the LARGE
`f100` series and the four canonical default-frequency aliases, intentionally
do not have LKH tours because TA-Prioritized and TA-Hybrid use these packaged
tours for offline assignment.

The offline TA methods consume a tour as follows:

```bash
./mapd \
  -m benchmark_instances/maps/benchmark_structured_small_a10.map \
  -t benchmark_instances/tasks/benchmark_structured_small_a10_fall.task \
  -a TA_PRIORITIZED \
  --tour benchmark_instances/lkh_tours/benchmark_structured_small_a10_fall.tour
```

Each tour contains every agent depot and task node exactly once. A tour is an
LKH task assignment/order, not a collision-free path plan. A representative
standard 10-agent tour completed all 500 tasks and passed collision checking.
The MG-MAPD tours are structurally valid LKH assignments, but the current
TA-Prioritized and TA-Hybrid path-planning layers did not complete the sampled
10-agent MG workload, so no end-to-end feasibility claim is made for those
tours.

`manifest.csv` records the exact map/task/tour pairing and LKH cost. Verify the
tour checksums with:

```bash
cd benchmark_instances/lkh_tours
shasum -a 256 -c SHA256SUMS
```

Regenerate the tours from the repository root with:

```bash
python3 scripts/generate_benchmark_lkh_tours.py --time-limit 1
```
